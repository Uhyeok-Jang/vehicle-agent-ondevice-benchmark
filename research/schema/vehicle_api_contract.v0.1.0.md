# Canonical Vehicle API Contract v0.1.0

Status: **working draft**  
Schema: [`vehicle_api_schema.v0.1.0.json`](vehicle_api_schema.v0.1.0.json)  
Registry: [`vehicle_api_registry.v0.1.0.json`](vehicle_api_registry.v0.1.0.json)

This is a language-independent, non-actuating simulator contract for comparing a lightweight Encoder parser with a generative SLM function caller. It is not an interface for direct control of a real vehicle.

## Decisions fixed for the draft

- The prediction envelope is exactly `{"calls":[...]}`. `schema_version` and provenance live in benchmark metadata and are not generated by either model.
- A source semantic unit maps to zero or one call. Calls retain source semantic-unit order.
- Primary scoring is strict ordered full-call exact match. Unordered call-multiset exact match is a secondary diagnostic for independent conjunctions.
- Complexity is computed after mapping from canonical `call_count`, not from raw intent labels.
- MAC-SLU/MIVS intent values are routing evidence, never canonical function names.
- Missing information is not guessed. A mapping can instead return `ambiguous`, `unsupported`, or `needs_context`.
- Percentages and levels are integers. HVAC temperature uses Celsius on a 0.5-degree grid. Qualitative relative magnitudes remain `default`, `small`, `medium`, or `large`; they are never converted to invented numeric deltas. These bounds are a mock runtime contract, not facts inferred from the corpora.
- Set-like arrays are sorted by the registry before serialization. Call order is never sorted for the primary target.
- There are no silent clamps, unit guesses, conflict resolution, duplicate-call collapse, or inferred negation.

## Pilot scope

The first schema deliberately recognizes only eight functions:

- `set_hvac_power`
- `set_hvac_temperature`
- `set_hvac_fan_speed`
- `set_window_position`
- `set_sunroof_position`
- `set_sunshade_position`
- `set_seat_climate`
- `set_seat_massage`

These are a transformation-engine pilot, not the final benchmark coverage claim. Airflow/source/mode, defogging, and seat-position functions are the first candidate extension. Display and audio follow, then lighting, UI/connectivity, and camera. A family is added only after its source selectors are mutually exclusive, its arguments can be normalized without guessing, and MAC train support is documented.

MIVS-only `应用名` is not promoted to a core system-app function until equivalent MAC train support exists; otherwise the supplementary test would measure function-OOV behavior rather than compositional transfer. Safety-sensitive exterior lighting and drive-mode commands remain outside this schema.

## Omission semantics

An omitted optional argument means only that the source did not specify it and the canonical function supports that partial command. It does not imply a hidden gold default.

- Omitted HVAC `zone` means an unqualified HVAC scope.
- Seat and window zones are required; an unqualified source unit therefore needs context or review.

Exact scoring does not treat an omitted argument and an explicit numeric value as equivalent.

For all aperture targets, absolute percentage `0` means fully closed and `100` means fully open or retracted. Named and qualitative-relative targets remain structurally distinct from percentages. Fractional source changes are never rounded to integer percentages.

## Explicitly unsupported in v0.1

- ADAS, steering, braking, autonomous parking, and direct longitudinal/lateral driving control;
- door, lock, tailgate, and horn actuation;
- charging actuation, reboot/reset, arbitrary touch/gesture/back operations, and OEM macros such as light shows or zero-gravity sequences;
- query-only state requests, complaints without an executable action, prohibitions, contradictory commands, and values outside the contract;
- functions deferred by the staged extension registry until their mapping gate passes.

## Carry-over for source frame fragments

`提供信息` is not a read/query API. A fragment may be completed only when it has an intrinsic typed signature or exactly one compatible anchor within the same source record and coordinated command. Family, object, or zone may be inherited; action and value may not. Search may be bidirectional because a modifier can precede its head. Zero or multiple compatible anchors, chains of unresolved fragments, cross-record inheritance, and type conflicts produce `ambiguous` or `needs_context` rather than a call.

## Freeze requirements

Version `0.1.0` remains a draft until the source alias tables, allow/deny lists, bounds, carry-over adjudications, and function-level coverage report pass manual review. Any semantic change after freeze requires a new schema version; spelling-only fixes do not mutate released benchmark targets.
